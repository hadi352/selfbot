# 🤖 سلف‌بات تلگرام فارسی (Telethon)

سلف‌بات (Userbot) ماژولار و کامل برای اکانت شخصی تلگرام - بیش از صد دستور در ۲۹ دسته: از ابزارهای روزمره، سرگرمی و فونت گرفته تا هوش مصنوعی، اتوماسیون، مدیریت گروه، جستجوی جهانی و سیستم پلاگین.

نقطه‌ی اجرا `main.py` است و کل منطق در پوشه‌ی `bot/` به‌صورت ماژولار سازمان‌دهی شده (پیشوند پیش‌فرض دستورات: `.`).

## ۱) سلف‌بات یعنی چی؟

این اسکریپت با **اکانت شخصی تلگرام خودتون** لاگین می‌شه - نه با یک بات جدا که از BotFather ساخته باشید. `API_ID`/`API_HASH` مستقیماً از پنل رسمی [my.telegram.org](https://my.telegram.org) گرفته می‌شه (همون مکانیزم رسمی‌ای که هر کلاینت شخص‌ثالث تلگرام، مثل خودِ اپ‌های موبایل/دسکتاپ، ازش استفاده می‌کنه) و با کتابخانه‌ی [Telethon](https://docs.telethon.dev) به یک Session وصل می‌شه.

نکات مهم که باید در نظر داشته باشید:

- **فقط پیام‌هایی که خودِ شما (owner) بفرستید** به‌عنوان دستور شناسایی و اجرا می‌شن؛ پیام‌های بقیه هیچ‌وقت دستور حساب نمی‌شن (مگر برای هندلرهای پس‌زمینه‌ای مثل فیلترها که عمداً روی پیام‌های دیگران کار می‌کنن).
- دستورات مدیریت گروه (`اخراج`/`مسدود`/`ارتقا`/`تنزل`/...) رو فقط در گروه‌هایی که خودتون واقعاً ادمین هستید استفاده کنید؛ تلگرام این سطح دسترسی رو خودش در سمت سرور چک می‌کنه.
- قابلیت‌هایی مثل ارسال خودکار (`.ارسال‌خودکار`) و تگ‌کردن همه (`.برچسب‌همه`) می‌تونن در صورت استفاده‌ی افراطی (فاصله‌ی خیلی کم، تکرار زیاد) توسط سیستم‌های ضداسپم تلگرام محدودیت روی اکانت ایجاد کنن؛ مقادیر پیش‌فرض پروژه برای کاهش این ریسک تنظیم شده‌ن (حداقل فاصله، batch کردن، سقف تعداد اعضا) ولی مسئولیت نهاییِ میزان استفاده با خودتونه.
- فایل `.env` یا مقدار `SESSION_STRING` معادل رمز عبور کامل اکانت شماست؛ هرگز جایی منتشرش نکنید.

## ۴) پیش‌نیازها

- **Python 3.12+** (تصویر Docker پروژه از `python:3.12-slim` استفاده می‌کنه)
- یک اکانت تلگرام + `API_ID`/`API_HASH` رایگان از [my.telegram.org](https://my.telegram.org)
- **PostgreSQL** - منبع اصلیِ داده‌های دائمی از این نسخه به بعد (نه فایل JSON)
- برای قابلیت‌های رسانه/OCR: `ffmpeg`، `tesseract-ocr` (+ بسته‌ی زبان فارسی `tesseract-ocr-fas`) و `fonts-dejavu-core` - همه‌شون در `Dockerfile` از قبل نصب شدن؛ اگر بدون Docker اجرا می‌کنید باید خودتون نصبشون کنید.
- (اختیاری) یک توکن بات از [@BotFather](https://t.me/BotFather) برای فعال‌سازیِ پنل دکمه‌ای (`.پنل`)
- (اختیاری) یک `AI_API_KEY` سازگار با فرمت OpenAI برای قابلیت‌های AI

## ۵) نصب و راه‌اندازی

### روش ۱: Railway (روش اصلی و پیشنهادی)

چون سرورهای Railway ترمینال تعاملی برای وارد کردن کدِ تاییدِ تلگرام ندارن، مرحله‌ی لاگین (گرفتنِ Session String) باید **اول روی سیستم خودتون** انجام بشه.

**۱. گرفتنِ Session String (یک‌بار، قبل از دیپلوی):**
```bash
pip install telethon python-dotenv
python generate_session.py
```
(`API_ID`/`API_HASH` رو قبلش توی یک فایل `.env` کنارِ `generate_session.py` بذارید.) شماره‌تلفن و کدِ تاییدی که تلگرام می‌فرسته رو وارد کنید؛ در آخر یک رشته‌ی طولانی چاپ می‌شه - همون رو نگه دارید.

**۲. ساختنِ دیتابیس PostgreSQL روی Railway:**
توی همون پروژه‌ی Railway → **New → Database → Add PostgreSQL**. Railway خودش یک متغیر محیطی `DATABASE_URL` می‌سازه و در صورت استفاده از Reference Variables به سرویسِ بات وصلش می‌کنه.

**۳. دیپلوی از طریق گیت‌هاب:**
1. پوشه‌ی پروژه رو به یک ریپوی گیت‌هاب پوش کنید.
2. Railway → **New Project → Deploy from GitHub repo** → ریپو رو انتخاب کنید.
3. Railway به‌خاطرِ `Dockerfile`/`railway.json` خودش بیلد و اجرا رو مدیریت می‌کنه:
   ```
   alembic upgrade head && python main.py
   ```
   یعنی هر دیپلوی/ری‌استارت، اول اسکیمای دیتابیس به‌روز می‌شه (idempotent) و بعد بات روشن می‌شه.

یا از طریق CLI:
```bash
npm i -g @railway/cli
railway login
railway init
railway up
```

**۴. تنظیمِ متغیرهای محیطی** (تب **Variables**):
- `API_ID`, `API_HASH`, `SESSION_STRING` (مرحله‌ی ۱)
- `DATABASE_URL` (اگر با Reference Variable خودکار وصل نشده)
- اختیاری: `PREFIX`, `TIMEZONE_OFFSET`, `CLOCK_INTERVAL`, `BOT_TOKEN`, `AI_API_KEY` (جدول کامل در بخش بعدی)

### روش ۲: Replit (جایگزین)

1. یک Repl از نوع **Python** بسازید و ۴ فایل `main.py`, `requirements.txt`, `generate_session.py`, `.env.example` رو آپلود کنید (پوشه‌های `bot/`، `migrations/` و بقیه هم لازمه کامل منتقل بشن).
2. در Shell: `pip install -r requirements.txt`
3. در تب **Secrets**: `API_ID`, `API_HASH` و اختیاری `PREFIX`/`TIMEZONE_OFFSET`/`CLOCK_INTERVAL`
4. یک‌بار `python generate_session.py` رو اجرا کنید و رشته‌ی خروجی رو با نامِ `SESSION_STRING` به Secrets اضافه کنید.
5. `main.py` رو اجرا (Run) کنید.

⚠️ Replit رایگان بعد از مدتی بی‌فعالیتی خاموش می‌شه؛ برای روشن نگه‌داشتنش معمولاً یک وب‌سرور کوچک (Flask) + پینگ دوره‌ای (مثلاً UptimeRobot) اضافه می‌کنن.

### روش ۳: اجرای محلی با Docker

```bash
docker build -t telegram-selfbot .
docker run --env-file .env telegram-selfbot
```

## عیب‌یابیِ سشن (SESSION_STRING)

**خطای `AuthKeyDuplicatedError`** یعنی تلگرام سشن رو به‌خاطر استفاده‌ی هم‌زمان از دو جا باطل کرده. رایج‌ترین علت‌ها:

1. **دو سرویس روی Railway با یک سشن** — اگه سرویس Web و Worker (یا هر سرویس دیگه) هر دو `python main.py` اجرا می‌کنن، فقط یکی باید سشن رو داشته باشه. بقیه رو پاک کن یا متغیر `SESSION_STRING` رو فقط توی یکی بذار.
2. **اجرای هم‌زمان روی سیستم شخصی + Railway** — سشن رو فقط یه جا اجرا کن.
3. **ری‌دیپلوی** — الان خود بات موقع دریافتِ SIGTERM اتصال رو تمیز قطع می‌کنه (۲ ثانیه فرصت برای ثبتِ قطعی)، پس این حالت دیگر نباید پیش بیاد.

راه‌حل در هر صورت: `python generate_session.py` روی سیستم خودت → مقدار جدید در `SESSION_STRING` → redeploy.
| `ASSISTANT_OFFLINE_GRACE` | `60` | مکثِ امن قبل از آفلاین‌شدن برای جلوگیری از روشن/خاموشِ مدام (ثانیه) |
| `ASSISTANT_SCHEDULE_MAX_WINDOWS` | `20` | سقفِ بازه‌های زمان‌بندیِ منشی |
| `AUTOPOST_MIN_INTERVAL_MINUTES` | `1` (توصیه: حداقل ۵) | حداقل فاصله‌ی مجاز ارسال خودکار |
| `CHANNEL_COPY_BATCH_SIZE` | `20` | تعدادِ پیام در هر درخواستِ فوروارد در `.کپی‌کانال` (سقفِ تلگرام ۱۰۰) |

نام‌های انگلیسیِ قدیمی (مثل `.help`, `.ping`) هم برای سازگاری کار می‌کنن؛ زیرِ هر دسته معادلِ لاتینش هم آورده شده.

```

`.فیلترپورن` نیازمندِ `AI_API_KEY` با مدلی است که از ورودیِ تصویر پشتیبانی کنه؛ اگه کلید نباشه یا مدل Vision نداشته باشه، فیلتر **fail-open** می‌کنه (به‌جای حذفِ اشتباهیِ عکسِ سالم، کاری نمی‌کنه). دستورِ `.فیلترپورن تست` با ریپلای روی یک عکس، پاسخِ خامِ AI یا خطای دقیق رو مستقیم نشون می‌ده - برای عیب‌یابیِ سریع بدونِ نیاز به لاگ سرور.

```

```
**چطور کار می‌کند؟** پیام‌های متنی (و کپشن‌ها) در جدولِ `message_index` ذخیره و با embedding (`/embeddings`) برداری می‌شوند. با `.پرسش` (وقتی سوال درباره‌ی گفتگوی قبلیِ خودتان باشد، مثل «آخرین باری که … چی گفتیم؟») یا `.پیام‌یاب`:

1. پیام‌های مرتبط بر اساسِ **معنا** پیدا می‌شوند، حتی با کلماتِ متفاوت («خرید گوشی» ⇠ «می‌خوام یه موبایل بخرم»)؛ با یک جستجوی کلمه‌ایِ فارسی‌-نرمال‌شده ترکیب می‌شود.
2. نامِ مخاطب («با علی …») و زمان («دو ماه پیش»، «دیروز») از سوال خوانده می‌شود؛ «آخرین باری …» جدیدترین گفتگوی مرتبط را مبنا می‌گیرد.
3. پیام‌های نزدیکِ هم در یک چت به یک «گفتگو» تبدیل و با پیام‌های اطرافشان به مدل داده می‌شوند؛ مدل پاسخ/خلاصه می‌دهد.
4. زیرِ پاسخ، **منابع** می‌آید: نامِ شخص، تاریخِ شمسی، پیامِ اصلی و **لینکِ مستقیمِ پیام**.

اگر embedding در دسترس نباشد، جستجو خودکار با کلماتِ نرمال‌شده (و بسطِ کلمات با AI در صورتِ وجودِ `AI_API_KEY`) کار می‌کند. اگر `AI_API_KEY` نباشد، فقط پیام‌های پیداشده نشان داده می‌شوند.

**🔒 حریمِ خصوصی:** ایندکس *opt-in* است (پیش‌فرض خاموش). متنِ پیام‌ها در دیتابیسِ خودتان ذخیره و برای ساختنِ embedding به سرویسِ `AI_EMBED_API_BASE` فرستاده می‌شود. «پیام‌های ذخیره‌شده» و دستورها ایندکس نمی‌شوند؛ پیام‌های ویرایش/حذف‌شده‌ی طرفِ مقابل در ایندکس هم به‌روز/حذف می‌شوند؛ `.ایندکس نادیده` یک چت را کنار می‌گذارد و `.ایندکس پاک تایید` همه‌چیز را پاک می‌کند. چون نتیجه شاملِ پیام‌های *چت‌های دیگر* است، به‌طورِ پیش‌فرض در «پیام‌های ذخیره‌شده» فرستاده می‌شود (نه در چتی که دستور را زده‌اید).

### 🧠 روترِ دستوریِ هوشمند
```
.هوش <جمله‌ی آزاد>    مثال: .هوش فردا ساعت ۹ یادم بنداز به علی زنگ بزنم
.هوش تایید            اجرای پیشنهادِ تشخیص‌داده‌شده
.هوش لغو
```
یک جمله‌ی محاوره‌ای می‌گیره و با AI تشخیص می‌ده کدوم دستور مدنظرتونه. بخش‌های پشتیبانی‌شده: یادآوری/زمان‌بند، یادداشت‌ها، ابزار (محاسبه/ترجمه/تبدیلِ‌ارز/پسورد)، پروفایل (بیو/نام)، فونت، و چندتا دستورِ سرگرمی. مدیریتِ گروه/فایل/اتوماسیونِ دائمی **عمداً پوشش داده نشدن** (مستقیم از دستورِ خودشون استفاده کنید). قبل از هر اجرایی خلاصه‌ی تشخیص‌داده‌شده رو نشون می‌ده و منتظرِ تاییدِ صریح می‌مونه - چیزی خودکار انجام نمی‌شه.

### 🔊 صوت و متن

.رونویسی                   (با ریپلای روی ویس) تبدیل به متن
.رونویسی <سوال/درخواست>    رونویسی + پرسیدنِ همون سوال از AI (نیازمندِ AI_API_KEY)
.متن‌به‌صوت <متن>           تبدیلِ متن به ویس (یا ریپلای روی پیامِ متنی)
```
رونویسی از موتورِ رایگانِ گوگل (`SpeechRecognition`) و متن‌به‌صوت از `edge-tts` استفاده می‌کنه - **بدونِ نیاز به `AI_API_KEY`**، فقط اتصال به اینترنت لازمه (و ffmpeg، که در Dockerfile نصبه).

### 📊 آمار
```
.آمار              خلاصه‌ی کلی: دستورات، پیام‌ها، ارسالِ‌خودکار، خطاها، uptime + پراستفاده‌ترین‌ها
.آمار چت‌ها         به‌تفکیکِ هر چت

```

### 📦 کپی کانال
```
.کپی‌کانال شروع @مبدا @مقصد                    فورواردِ همه‌ی پست‌ها (بدونِ برچسبِ Forwarded from)
.کپی‌کانال شروع @مقصد + ریپلای روی پستِ مبدأ   فقط مقصد را بده؛ مبدأ از پستِ ریپلای‌شده گرفته می‌شود
.کپی‌کانال شروع @مقصد از 1403/05/01 + ریپلای   مقصد از آدرس، تاریخ هم اعمال می‌شود، مبدأ از ریپلای
.کپی‌کانال شروع @مبدا @مقصد از 1200            از پیامِ شماره‌ی 1200 به بعد
.کپی‌کانال شروع @مبدا @مقصد از 1403/05/01      از یک تاریخِ شمسی به بعد (میلادی هم می‌شه: 2024-08-22)
.کپی‌کانال شروع @مبدا @مقصد از امروز           امروز/دیروز/پریروز (با ساعتِ اختیاری: ساعت 10:30)
.کپی‌کانال شروع @مبدا @مقصد ازاین‌بعد          تا آخر کپی کن و بعد هر پستِ تازه را هم خودکار کپی کن 👀
.کپی‌کانال شروع @مبدا1,@مبدا2,@مبدا3 @مقصد    چند کانال هم‌زمان (یک کارِ گروهی با پیشرفتِ جمعی)
.کپی‌کانال شروع پوشه:3 @مقصد                   همه‌ی کانال‌های یک پوشه (شماره را از `.کپی‌کانال پوشه‌ها`)
.کپی‌کانال شروع @مبدا @مقصد با‌نام              با نامِ کانالِ مبدأ (برچسبِ Forwarded from)
```
کانال‌های **خصوصی** (بدونِ `@username`): چون آیدیِ عددی‌شان را نمی‌دانید، سه راه دارد —
```
.کپی‌کانال پیدا اخبار                          🔍 جستجو بینِ همه‌ی چت‌هات (اسمِ فارسی هم قبول است) + آیدیِ کاملِ هر کانال
.کپی‌کانال ذخیره اخبار مهم t.me/c/1234567890   💾 اسمِ دلخواه (چندکلمه‌ای هم می‌شود) برای یک کانال — بعداً همان اسم را در «شروع» بده
.کپی‌کانال شروع @مقصد                          + ریپلای روی هر پستی از آن کانال → مبدأ همان کانال می‌شود
.کپی‌کانال اسم‌ها / .کپی‌کانال پوشه‌ها           لیستِ اسم‌های ذخیره‌شده / شماره‌ی پوشه‌ها
```
مدیریت: `.کپی‌کانال وضعیت` (پیشرفت، تاریخِ شروع، حالتِ «از این به بعد») • `توقف [شماره]` • `ادامه [شماره]` • `لیست` • `حذف <شماره>`.
«ادامه» روی یک کارِ **تمام‌شده** یعنی «فقط پست‌های تازه»: کپی از پیامِ آخرِ کپی‌شده به بعد ادامه می‌یابد و هیچ پیامی دوباره کپی نمی‌شود — کافی است بعد از انتشار پست‌های جدید `.کپی‌کانال ادامه <شماره‌ی کار>` را بزنید.
مقصد باید کانالی باشد که در آن ادمین (با دسترسیِ انتشار) هستید. کانال‌هایی که مالکشان «محتوای محافظت‌شده» (Restrict Saving Content) فعال کرده، طبقِ قوانینِ خودِ تلگرام قابلِ فوروارد نیستند.
راهنمای کامل: [`CHANNEL_COPY_GUIDE.md`](CHANNEL_COPY_GUIDE.md)

## ۹) سیستم پلاگین

بات از نصب، حذف و ری‌لودِ آنیِ پلاگین (بدونِ ری‌استارت) پشتیبانی می‌کنه.

فرمتِ یک پلاگین (همون الگوی Telethon که هندلرهای داخلی استفاده می‌کنن):
```python
from bot.runtime import client
from telethon import events

@client.on(events.NewMessage(outgoing=True, pattern=r"^\.hello$"))
async def hello(event):
    await event.edit("Hello from plugin ✅")

commands = ["hello"]

async def startup():
    pass

async def shutdown():
    pass
```

- برای Unload تمیز، لودر تابع‌های callback تعریف‌شده توسطِ پلاگین رو ردیابی می‌کنه؛ اگر پلاگین هندلر رو پویا ثبت می‌کنه، اون callbackها باید در لیستِ سطحِ ماژولِ `handlers` باشن.
- **پایداری روی Railway:** چون کانتینرهای Railway تضمین نمی‌کنن فایل‌های نوشته‌شده در زمانِ اجرا بعدِ یک دیپلویِ جدید باقی بمونن، برای پلاگین‌های نصب‌شده‌ی دائمی یک Railway Volume به `/data` وصل کنید و `PLUGIN_INSTALL_DIR=/data/plugins` رو ست کنید. پوشه‌ی داخلیِ `plugins/` (پلاگین‌های built-in) از این جدا می‌مونه، پس Volume باعثِ مخفی‌شدنِ built-inها نمی‌شه.
- **امنیت:** یک پلاگینِ پایتونی با همون سطحِ دسترسیِ خودِ سلف‌بات اجرا می‌شه. فقط کدی رو نصب کنید که بهش اعتماد دارید. لودر حجم/UTF-8/سینتکسِ پایتون رو قبل از بارگذاری چک می‌کنه، ولی این‌ها **sandbox نیستن**.

## ۱۱) نکات امنیتی و مسئولیت‌پذیری

- فایلِ `.env` یا `SESSION_STRING` رو جایی منتشر نکنید - معادلِ رمزِ کاملِ اکانتتونه.
- دستورهای مدیریتیِ گروه (`.اخراج`/`.مسدود`/`.ارتقا`/`.تنزل`) رو فقط توی گروه‌های خودتون که ادمینشون هستید استفاده کنید.
- فاصله‌ی `CLOCK_INTERVAL` رو خیلی کم (زیرِ ۳۰ ثانیه) نکنید تا ریسکِ محدودیت از طرفِ تلگرام کم بمونه؛ همین‌طور `.ارسال‌خودکار` و `.برچسب‌همه` رو با احتیاط و فاصله‌ی معقول استفاده کنید.
- فایلِ خروجیِ `.پشتیبان تنظیمات` شاملِ رمز یا Session نیست، ولی متنِ یادداشت‌ها و تنظیماتِ منشی/ارسالِ‌خودکارتون توشه - جای امنی نگهش دارید.
- `.بازیابی` فقط با ریپلای‌کردنِ خودِ owner روی پیامِ outgoing کار می‌کنه، پس کسی جز خودتون نمی‌تونه از راه دور تنظیماتتون رو تغییر بده.
- `.پرسش`/`.خلاصه`/`.ترجمه‌هوشمند` و منشیِ AI متنِ پیام‌ها رو به یک سرویسِ بیرونی (OpenAI یا هر endpointی که تنظیم کردید) می‌فرستن - برای چت‌های حساس/خصوصی با احتیاط استفاده کنید.
- پلاگینِ نصب‌شده با سطحِ دسترسیِ کاملِ سلف‌بات اجرا می‌شه؛ فقط از منابعِ مطمئن نصب کنید.

### 📚 دانشِ شخصی (Knowledge Base)
```
.دانش افزودن <عنوان> <متن | ریپلای>   پرونده‌ی دانش
.دانش لیست / جستجو <عبارت> / حذف <عنوان>
```
هر چیزی که در دانش ذخیره کنی، AI در `.پرسش`/عامل به‌عنوانِ «دانشِ شخصی» می‌بیند و از آن جواب می‌دهد.

### 🎭 شخصیتِ AI
```
.شخصیت                                نمایشِ فعلی + پیش‌فرض‌ها
.شخصیت <حرفه‌ای|دوستانه|کوتاه|برنامه‌نویس|طنز|پیش‌فرض>
.شخصیت سفارشی <توضیحِ آزاد>
```
شخصیت در همه‌ی مسیرهای AI (پرسش/عامل) اعمال می‌شود.

### 🧠 عامل (AI Agent)
```
.عامل روشن / خاموش / وضعیت
```
وقتی روشن باشد، `.پرسش <هرچه>`: Context Engine (حافظه + کارها + یادداشت‌ها + دانش) را می‌سازد، در صورتِ نیاز **ابزار** صدا می‌زند (ثبت/انجامِ کار، جستجوی حافظه/دانش/وب)، مدلِ مناسب را بر اساسِ نیت انتخاب می‌کند (AI_MODEL_FAST/CODING/REASONING) و پاسخ‌های فنیِ بلند را یک‌بار self-check می‌کند.
